# 絶ケフカ readiness 監査結果と残課題

「タイムライン・AoE予兆・読み上げ・UI・重複ログ/重さ・重複読み上げ・2体タイムラインに問題が無いと言い切れるか」
という問いに対する、敵対的監査（具体的な失敗ケースを探す方式）の結果と対応のまとめ。

## 結論（正直な要約）

**「絶対に問題が無い」とは言い切れない。** 理由は2種類に分かれる：

1. **修正可能なコード欠陥** → このセッションで潰した（下記「修正済み」）。
2. **本質的に明日まで判定不能な残存** → コード修正では消せない（下記「残課題」）。
   絶ケフカは 2026/6/2 実装で、専用トリガー JSON・実 cast_id・テザー種別・同名分身の有無・
   ノーキャスト即時技の構成が**録画するまで未確定**。これらに依存する項目は、明日の録画で
   検証・データ投入して初めて「言い切れる」状態になる。

つまり**コードの欠陥は無くした**が、**データ未整備に由来する不確実性は残る**（リアクティブ読み上げが
大半を吸収するので全滅直結ではない）。

## 修正済み（このセッション）

| 項目 | 内容 |
|---|---|
| PERF-ALLOC-01 | `InMemoryEventBus.Publish` の publish 毎 2 配列確保を**コピーオンライトでゼロalloc化**。raid-wide フレームの GC churn を解消 |
| PERF-LOG-01 | `RecordingSession` の `AutoFlush=true`（毎イベント同期ディスク書込＝フレームブロック）を**64件ごとのバッチ flush** に変更 |
| TL-02 | sync_point 経路の 30 秒ジャンプガードを撤廃（`distance≤tolerance` で既に保証されるため冗長・有害だった）。tolerance>30s の正当な再アンカーが棄却される問題を解消 |
| TWB-02 / TL-01 | 単一グローバル同期オフセットを**発生源（ボス）別オフセット**に拡張（表示バー）。2体フェーズで両ボスが独立ドリフトしてもバーが振動しない。global は据え置きで読み上げ等は不変、未記録 source はフォールバック＝退行なし |
| DUP-01 | ユーザー mechanic が読み上げるキャストでは、generic な**自動安置コール（TTS）を抑制**（視覚は残す）。mechanic が視覚のみなら抑制しない graceful 設計 |

これらは x64 フルビルド 0警告/0エラー、テスト 211 PASS で確認済み。

## 残課題（コード修正では消せない／夜前にリスクを取って直すべきでない）

各項目に「なぜ言い切れないか」「当面の代替」「録画後の正攻法」を明記する。

### R1. 重複読み上げ：事前警告 + 実発火（DUP-02）
- 攻略 mechanic に `advance_warning_sec>0` を付けると、NoteReminder が T-warn で読み、MechanicTrigger が T=0 でも同文言を読む（warn 秒差で二度読み）。
- **直さない理由**：NoteReminder の発話条件（録画から時刻解決成功・role/job一致・phase/branch許可）と FireMechanic の発火条件が**一致しない**。`advance_warning_sec>0` で機械的に T=0 を抑制すると、NoteReminder が発話しないケース（時刻解決失敗等）で**主コールごと消える＝無音化＝事故**。非対称リスク（二度読みは非致命、無音化は致命）のため抑制しない。
- **当面**：二度読みは許容（事前警告＋実行確認とも解釈でき非致命）。気になる場合は `advance_warning_sec` を使わず、事前警告は別文言にする。
- **正攻法**：NoteReminder が実際にスケジュールした mechanic を共有レジストリで記録し、FireMechanic はそれを参照して TTS のみ抑制（視覚は残す）。

### R2. 2体タイムライン：同名2体の帰属（TWB-01）
- 録画予測の発生源は**表示名の文字列のみ**（entity-id/序数を持たない）。ケフカの分身など**同名2体**が同名技を同時詠唱すると、1カラムに合流し片方のバーが dedup で消える。
- **直さない理由**：録画集計スキーマ（`EventKey`）に source_id/序数を足す変更で、録画フォーマット互換に影響。実際に同名分身が出るか（別名2体なら問題なし）は録画するまで不明。
- **当面**：別名2体なら 2 カラムで正しく分離（実装済み）。同名分身でもリアクティブ読み上げは別経路で鳴る（タイムライン**表示**のみの問題で読み上げは消えない）。
- **正攻法**：`EventKey` に source_id を追加、または source を「名前#序数」で正規化して同名インスタンスを区別。

### R3. AoE予兆の事前表示（AOE-PRE / GIM-01）
- 画面に AoE 危険域/安置を「事前」に描くのは主に **PredictedObjectSpawnService**（録画2戦＋手動学習が前提）と、リアクティブな **AutoTelegraph/ActorTrackedAoe**（ゲームの詠唱が始まった後に描く）。
- **初日（録画なし）は予兆の事前描画が出ない**。ゲームの詠唱バー表示後にリアクティブで出る。ノーキャスト即時技は着弾フィードバック（事後）になる。
- 録画ベースの「予測床塗り/ミニマップ事前描画」メソッドは現状デッドコード（変身演出での actor 名衝突→中央誤描画の回帰を避けるため意図的に無効化された経緯）。**安易に復活させると既知の誤描画バグを再導入する**ため、夜前には触らない。
- 自己対象キャスト（target_id=source_id）の AoE はキャスト経路で skip される（演出/召喚の誤描画回避）。ボスが自分対象で予兆付き AoE を撃つ場合は沈黙しうる（OnActionUsed の caster 中心救済はあるが OnCastStart には無い非対称）。
- **当面**：ゲーム自身の予兆（オーメン）＋リアクティブ読み上げで回す。安置プリセット（field_marker/screen_arrow/arena_view/knockback_projection）で安置を可視化。
- **正攻法**：録画→`predicted_object_spawns`/`object_aoe_rules` を整備し起動時自動学習を配線。誤描画を避けつつ予測描画を復活。自己対象 skip をキャスト経路でも caster 中心救済に揃える。

### R4. パフォーマンス：Capture の重複 ObjectTable 走査（PERF-SCAN-01）
- 4 つの Capture が各フレーム個別にフル ObjectTable を走査し、StatusCapture の source 解決が線形探索。add 多数フェーズで 1ms/frame 予算を圧迫しうる。
- **直さない理由**：共有スナップショット化は 4 サービス＋解決経路の改修で回帰範囲が広い。実機録画での計測前に夜前に入れるべきでない。
- **当面**：ログ氾濫は FrameErrorThrottle で抑制済み。重さは add-spam 局面に限定。EventBus/録画 I/O の重さは本セッションで解消済みなので複合悪化は緩和。
- **正攻法**：毎フレーム1回だけ走査して `Dictionary<uint, IGameObject>`（EntityId/ObjectId 両キー）を共有し、各 Capture は O(1) 参照。

### R5. タイムライン精度：JSON 未整備の初日（TL-03）
- 専用トリガー JSON（sync_points/branches/strategy_profiles の phase 注釈）が無い初日は、フェーズ/分岐の絞り込みが効かず**録画にある全フェーズ・全分岐の技が録画時刻順に同時表示**される。開幕分岐の確定前に来ない方の技も並ぶ。
- **当面**：リアクティブ読み上げ（実発火）が分岐・フェーズを吸収するので全滅しない。タイムライン**表示**を過信しない。
- **正攻法**：録画後に sync_points / branches / phase 注釈を定義する（運用ノート §1 の手順）。

### R6. 純VFXテザー（GIM-02）
- 付随ステータスの無いテザー（Hyperdrive 近遠等）はライブ捕捉未実装で沈黙。
- **当面**：付随 status_id があれば `status_gain`+`target` でコール。純 VFX は人力（運用ノート §2.1）。
- **正攻法**：録画でテザー種別 ID/オフセットを確定してから `TetherCapture` を実装（誤読は全滅誘導のため拙速に載せない）。

### R7. AA バー二重表示（TL-05・軽微）
- 同期オフセット>0.75s 時、ライブAAタイマーと予測AAバーが時間窓を外れて二重表示しうる（AAバーのみの表示上の軽微事象）。
- **当面**：表示上のみ・最重要度の低いAAバー。読み上げには影響しない。
- **正攻法**：ライブAA存在時に同 source の最近接予測AAをオフセット非依存で1本除去。

## 当日の運用指針（残課題を踏まえて）

1. **録画 ON で数戦**。実 cast_id・テザー種別・同名分身の有無・ノーキャスト技を確定。
2. リアクティブ読み上げは ID 差し替え前から動く。**タイムライン表示は補助**と割り切る（初日は全フェーズ表示）。
3. テザー・自己対象 AoE・ノーキャスト即時技は**沈黙しうる**ので、コール担当に事前周知。
4. 録画後に sync_points / branches / phase 注釈 / predicted spawns を整備すると、タイムライン精度と事前表示が段階的に向上する。
