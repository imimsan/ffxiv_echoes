# 絶ケフカ（絶妖星乱舞）運用ノート

明日の実戦投入に向けた **既知の制約と人力代替手順**、および直近の readiness 改修のまとめ。
ツールが「できること／できないこと」を把握し、できない部分は人力で埋めるための実務メモ。

対象バージョン: `fix/phase-transition-reset` ブランチ（本ノート作成時点）。

---

## 1. 初日の立ち上げ手順（録画 → トリガー実装）

1. **録画 ON のまま 1 戦**して `recordings/*.jsonl` に実データを貯める（`auto_record: true`）。
2. ログから **実 cast_id** を取得し、サンプル `絶妖星乱舞.json` のプレースホルダ ID
   （`0xPHASE2_START`, `0xP5_NARROW_SAFE` 等）を差し替える。
3. リアクティブ読み上げ（実発火ベース）は ID 差し替え前から動く。**まずは録画を回すことが最優先**。
4. タイムライン予測は「録画してから 1 戦」で出始める。HUD が空でも異常ではない。

> サンプルの `enabled: false` トリガー（後述の激狭安置）は**参考例**。録画後に実形状を入れて有効化する。

## 2. ツールでは対応できない／人力で埋めるギミック

### 2.1 テザー（Hyperdrive 系・距離切り）
- `tether` / `tether_remove` の**トリガー型とマッチャは追加済み**（`EventMatcher`）が、
  **ライブ捕捉層（TetherCapture）は未実装**。
  - 理由：FFXIVClientStructs のテザー対象フィールドはゲームパッチでオフセットが壊れやすく、
    誤読すると**誤った発生源/対象でコール＝全滅誘導**やクラッシュになりうる。
    ID/オフセットを録画で確定するまでライブ読み取りは載せない方針（安全優先）。
  - `tether` 型は録画再生（`FfxivEchoes.Replay`）や将来の `TetherCapture` がテザーを発行したとき即トリガー化できるよう先に用意したデータモデル。
- **当日のライブ運用は以下で代替**：
  - テザーに **付随ステータスがある**なら `status_gain` + `target` でコールできる（最優先で使う）。
  - 純 VFX テザー（ステータス無し）は捕捉できない。**距離を取る/切る指示は人力**。
  - clone 出現自体は `object_appear` で検知できるので、出現コール＋固定指示で補う。
- `tether` マッチの書き方（録画再生／将来捕捉用）：`status_id`=テザー種別ID、`duration_range`=source-target 距離 m、`source`/`source_id`=発生源（通常ボス）、`target`=被テザー対象、として既存フィールドを流用する。

### 2.2 ノックバック（着地点予測）— **`knockback_projection` プリセットを実装**
- `safe_zone.method: "knockback_projection"` で **self を source から外向きに `distance` 投射した着地点**を計算する（`between_actors` の「中点」とは別物）。`direction_call` / `field_marker` / `screen_arrow` のいずれにも渡せる。
- params：
  - `source`：KB 発生源（`self`/`boss`/`arena_center`/アクター名／`[x,y,z]`。既定 `boss`）。
  - `distance`：吹き飛び量 m（**技ごとに実測値を直書き**。耐性無し基準。既定 15）。
  - `clamp_to_arena`（既定 true）＋ `arena_radius`：**円形アリーナ半径を指定したときだけ**境界で丸める。
    **未指定なら clamp せず純投射** ＝ 境界外の着地点をそのまま返すので「落ちる」警告に使える。
- 符号は `dir = normalize(self - source)`（外向き）で固定し、**逆向き（AoE 中心へ誘導）にならないことをテストで保証**済み。
- 例（中央 KB で落下回避の方向を出す）：
  ```json
  { "type": "screen_arrow", "from": "self",
    "to": { "method": "knockback_projection",
            "params": { "source": "arena_center", "distance": 18, "clamp_to_arena": false } } }
  ```
- 注意：`distance`（KB量）はプラグインが知り得ないので**サンプルに実測値を入れる運用前提**。間違えると着地点がズレ「安全と誤提示」になる。矩形アリーナの厳密 clamp は未対応（円のみ）。

## 3. 安置プリセットの既知の制約（過信しない）

| preset | 制約 | 実戦での注意 |
|---|---|---|
| `intersection` | 全制約を満たす点ではなく**結果の重心（妥協点）**を返す簡易実装 | 複合制約を過信しない。重心が無人地帯になり得る |
| `inverse_of_telegraph` | **self に向く扇/直線専用**。形状解析はせずベクトル反転のみ | ドーナツ/PB に使うと反対側＝被弾側へ誘導。使わない |
| `telegraph_gap`（激狭安置） | 同心円サンプリング＋`clearance`（既定 1.0m）で縁ギリギリを避ける安全マージンを確保。極端に狭い隙間は依然取りこぼし得る | 安全点が見つからなければ `null`（無音）で安全側。`clearance` を上げると安全寄り（隙間が狭いと無音化）。鵜呑みにせず目視併用 |
| `find_actor_without_status`（塔反転） | 無ステータス候補が**複数**だと `select`（nearest/farthest）指定が無い限り `null`（誤コール回避） | `name_contains` / `npc_base_id` で 1 体に絞る。塔/安置の逆指しは全滅なので安全側 |

`facing_deg` / `rotation_deg` の角度規約は **0=南(+Z) / +X=東 / CCW(反時計)が正**。
render 系（0=東）と異なるので、render 角で書くと 90° ずれて安置が回る。符号は必ず検算する。

## 4. ランダム分岐（開幕分岐）

- 開幕の分岐は **リアクティブ読み上げ（実発火）が吸収**するので全滅はしない。
- 分岐確定までの数秒はタイムライン HUD に分岐技が出ない（**共通のみ表示**が既定ポリシー）。
- 録画からの分岐検出は初日サンプル数が少ないと出にくい。`window_sec` を十分長めに取る。

## 5. 2 体フェーズ（タイムライン HUD）

- 表示中に**非共通ソース（＝ボス）がちょうど 2 体**検出されると、HUD が **左右 2 カラム**に分かれ各ボスの予定を時系列で分離表示する（1 体時は従来の 1 カラム）。
- 各カラムは**ボス色のタグ帯**＋ボス名見出し付き。先頭に**現在フェーズ名**を表示。
- 左右の割り当ては**ボス名で安定ソート**するので、詠唱が進んでもカラムが左右に入れ替わらない。
- カラム内で**ボス本人の技はボス色帯／共通ノートは中立グレー帯**にして発生源を見分けやすくした。
- **3 体以上**（クローン多体・add 混在・未解決ソース）検出時は 2 カラムに畳まず、**ソース別グループ見出しの単一カラム**へフォールバックする（3 体目が左ボス名・色で誤帰属する事故を回避）。
- 行数は**カラムごとに独立**配分するため、片方のボスが行を使い切ってもう片方が消える事故を解消。
- **ウィンドウのリサイズを許可**（`NoResize` を外した）。2 体時にカラムが狭く技名が読み切れないときは**横に広げる**と表示文字数が自動で増える（幅は `imgui.ini` に永続）。技名はホバーで全文ツールチップ表示。

## 6. 音声（今回の改修）

- TTS は **単一ワーカーで順次再生**（優先度付きキュー）。新規発話で直前を**打ち切らない**ので、
  2 体同時/連続詠唱で重要コール（軽減/安置）が後発に消されない。
- **優先度** `priority`（`tts` / `direction_call` アクション、既定 0）：`1` 以上にすると
  **キュー内で通常コールより前に挿し、混雑で溢れても通常コールより先に守られる**。
  HP 全快コール（Heartless Angel）・軽減・安置など「埋もれると事故る」コールに付ける。
  ```json
  { "type": "tts", "text": "HP全快！", "priority": 1 }
  ```
- 積まれてから 2.5s 超過の発話は**手遅れとしてドロップ**（重要コールを遅らせない）。溢れ時は**最古の通常コール**から落とす（新しいコールほど現在の盤面を反映するため）。
- `tts` / `wav` は入口で **0.5s 窓 dedup**。`direction_call` / `proximity_feedback` の直呼び経路や
  WAV の二重再生もカバーし「北—北—北」のスタッターを抑制。
- 残る限界：優先度は 2 段（通常/優先）のみ。優先コールが連続すると優先同士は FIFO で待つ。

## 7. 同期（ラグ）

- 録画ベース予測に対する実戦時刻ズレは `SyncOffsetTracker` が補正する。
- フェーズ跨ぎで同一 cast_id が再利用されても誤オフセットへ飛ばないよう、録画経路は通常**ジャンプガード**を効かせ、フェーズ遷移直後の 1 回だけ大ジャンプ再アンカーを許可する。
- 既知の限界：単一グローバルオフセットのため、2 体が録画から相反する向きにズレると補正が振動し得る（per-source 化は中期課題）。事前警告が早すぎ/遅すぎを繰り返す場合は目視併用。

## 8. このノートで触れた readiness 改修の対応元

明日に向けたアセスメントの所見と対応：
- P0 サンプル無音（未解決トークン依存）→ 正規経路（`store_position`/`stored_position`）へ書き直し済み。
- 音声 dedup 一元化・TTS キュー化＋**優先度**・予測バーのフェーズ絞り込み・2 体 UI 2 カラム化（＋安定ソート／色帯／3 体フォールバック／リサイズ可）・schema/handler 乖離解消・find_actor フェイルセーフ・telegraph_gap clearance・output_format 補間・sync 安全化 → 実装済み。
- **KB 着地点予測（`knockback_projection`）→ 実装済み**（符号安全をテストで保証）。
- **テザー → トリガー型/マッチャは実装済み・ライブ捕捉は安全のため保留**（当面 `status_id` 代替＋人力。§2.1）。
- per-source sync・intersection/inverse_of_telegraph の形状対応 → **本ノートの人力代替で当面運用**（中期実装）。
