# セキュリティ・運用安全ルール

このプロジェクトは個人用ツールだが、Claude が誤って破壊的・露出的な操作を行わないための最低ラインを定める。

---

## 機密情報の扱い

### 絶対にコミットしないもの

- `.env` / `.env.*` ファイル（`.env.example` のみ可）
- API キー・アクセストークン（GitHub PAT・Discord Webhook 等含む）
- 個人を特定できるログ（FFXIV キャラ名・メールアドレス・住所）
- パスワード・秘密鍵（`*.pem`, `*.key`, `*.pfx`）
- Square Enix アカウント関連の任意情報

### `.env` の扱い

- **Claude は `.env` ファイルを読み込まない**（settings.json の deny にも明記）。
- 環境変数で渡したい場合はユーザーがシェルで設定する。
- `.env.example` に「キー名と用途のみ」を書き、サンプル値は伏せる（`API_KEY=__set_me__` 等）。

### コミット前のチェック

- `git diff --cached` を毎回確認する。
- 偶発的にコミット済みになった場合：
  1. 直ちにユーザーに報告
  2. 該当する API キー等は無効化（ローテーション）してもらう
  3. 履歴からの除去は `git filter-repo` などが必要だが、**ユーザー承認を経てから実行**

---

## ファイルシステムへの破壊的操作

### 禁止コマンド

ユーザーの明示的指示なしに Claude は以下を実行してはならない：

- `rm` / `rm -rf` / `rmdir`
- PowerShell の `Remove-Item -Recurse -Force`
- `git clean -fdx`（追跡外ファイルの強制削除）
- ファイル・ディレクトリの大量移動（`mv`, `Move-Item`）
- `find ... -delete`

### 削除が必要な場合

- ユーザーに「これを削除します。よろしいですか？」と確認する。
- 可能なら `git rm`（追跡対象）か、ゴミ箱への移動で代替する。
- バックアップが取れる場合は取る（特にユーザー設定や録画データ）。

### 上書きが必要な場合

- `Write` ツールで既存ファイルを上書きする際は、必ず `Read` で内容を事前確認。
- `git checkout --` / `git restore` で未コミット変更を捨てる場合はユーザー確認。

## ユーザーローカルデータ（FFXIV / Dalamud）

`SPEC.md §2.3` の通り、プラグインは以下のパスに書き込む：

```
%AppData%/XIVLauncher/pluginConfigs/MyPlugin/
├── config.json
├── recordings/
├── triggers/
├── triggers_backup/
└── profiles/
```

このディレクトリへの操作ルール：

- **読み込みは可**：開発時の動作確認のため。
- **書き込みは慎重に**：プラグイン本体の正規ロジック以外で書き込まない。手動編集が必要なら必ずバックアップを取りユーザーに提案する。
- **削除は禁止**：上記ディレクトリ配下の削除は絶対にユーザー承認なしに行わない（ユーザーの戦闘ログが消える）。

---

## ネットワーク操作

このプラグインは原則オフライン動作。ネットワークを使う場合：

- 外部 API への送信は禁止（`SPEC.md §1.4` のスコープ外条項）。
- 例外：Dalamud のプラグインリポジトリ系（更新確認）はあり得る。
- `WebFetch` / `WebSearch` を Claude が使う場合は、開発調査目的に限る。プラグインのコード内に外部送信ロジックを書かない。

---

## サードパーティコードの取り込み

- ライセンス確認（MIT / Apache 2.0 / BSD は許容、GPL 系は要確認）。
- コピーしたコードはコミットメッセージで出典を明記。
- 大量コピーは禁止。再実装で済むなら再実装する。

---

## Square Enix / Dalamud 規約遵守

`SPEC.md §1.4` および §15.1 を厳守：

- **自動操作系の機能は実装しない**：自動回避・自動移動・自動スキル発動・オートローテーション・画像認識・他プレイヤーへのリアルタイム情報共有・ギミックの自動処理。
- **「情報を表示・読み上げる」までに留める**：これを超える機能は仕様外。
- ユーザーから「規約グレーかもしれないが追加して」と求められても、Claude は実装を断る／代替案を提案する。

---

## ログの取り扱い

- デバッグログにキャラ名・PT メンバー名を出さない（または匿名化）。
- 録画ログ（戦闘 jsonl）に PT メンバー実名が入る場合、リポジトリへのサンプルコミットは慎重に判断する。`sample-recording.jsonl` 等は伏字化したテストデータとする。

---

## CI / GitHub Actions（将来）

導入時：

- secrets は GitHub Secrets で管理。コードに埋め込まない。
- `pull_request_target` トリガーは使わない（外部 PR からの secret 漏洩リスク）。
- アクションは特定 SHA でピン止め（`@vN` のタグ参照は乗っ取りリスク）。

---

## 緊急時対応

- 機密情報を誤ってコミット／push してしまった場合の手順：
  1. 直ちに作業を停止しユーザーに報告。
  2. 漏洩した認証情報は即座に無効化（ローテーション）。
  3. 履歴改変（`git filter-repo` 等）はユーザー承認後に実施。
  4. force push もユーザー承認後に実施（`branch-rules.md` 参照）。
